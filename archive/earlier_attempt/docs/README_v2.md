# Can seisDAE recover earthquake arrivals recorded on an optical fiber?

This repository tests a denoising autoencoder trained on conventional seismometers against fiber-optic distributed acoustic sensing (DAS) records. It compares the released model, two forms of adaptation, and classical baselines. The experiment asks whether the P waveform, onset timing and amplitude survive denoising, and whether smaller earthquakes benefit more.

[Historical V2 report](archive/v2/report.md). The current editable documents and presentation are linked from [the final README](README.md).

The scalar provides an important control. A constant multiplier can reduce squared error while leaving the waveform shape and STA/LTA timing intact. SI-SDR removes the scale factor; signed CC, local amplitude ratio and first-excursion agreement check different aspects of fidelity. These are comparisons to a recorded reference containing residual field noise. They do not measure earthquake detection recall on a continuous stream.

## Reproduce the study

Use Linux or WSL2 on Windows with Python 3.12. From the extracted repository root, install Pandoc and LibreOffice for report export. For example, on Ubuntu:

```bash
sudo apt-get update
sudo apt-get install -y pandoc libreoffice-writer
conda env create -f environment.yml
conda activate seisdae-das
bash run_all.sh
```

A Python virtual environment also works:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-v2.txt
bash run_all.sh
```

The one-command workflow runs the tests, executes all notebooks, verifies the original scores, retrains the head and last decoder block, evaluates the frozen test predictions, runs all development experiments, compares the new tables against the release and rebuilds the report and slides. The prepared waveforms, initial checkpoints and alternate-background excerpts are included. Once dependencies are installed, the default run needs no download, GPU, account or API key. The matrices in `runs/` are temporary. Delete that directory for a completely fresh run. Standard CPU TensorFlow 2.16.2 is pinned for installation; the verified execution used the CPU-only distribution of the same release with tf-keras 2.16.0. Direct requirements are in [requirements-v2.txt](requirements-v2.txt). For the exact Linux/Python dependency versions, add `-c constraints-linux-py312.txt` to the pip install command. See [the run log](CHANGELOG.md).

### Run only the part you need

| Goal | Command |
|---|---|
| Run unit and regression tests | `python -m unittest discover -s tests -v` |
| Check the packaged V2 results and invariants | `python -m src.verify results_v2 --v2` |
| Run and verify the **original** benchmark | `python -m src.evaluate --out runs/evaluation` then `python -m src.verify runs/evaluation` |
| Rebuild the report, diagrams and slide deck from packaged numbers | `python -m src.v2.report` (the rank figure is generated by `python -m src.v2.failures`) |
| Execute all seven notebooks in process | `python scripts/execute_local.py` |
| Execute with standard Jupyter on a socket-enabled host | `jupyter nbconvert --to notebook --execute --inplace --ExecutePreprocessor.timeout=1800 notebooks/*.ipynb` |
| Denoise a full **observed** field clip | `python -m src.field --event 71123139 --out runs/field` |

Each notebook sets the project import path relative to its working directory. Notebook 07 saves transient waveform outputs for secondary scoring. The fallback uses IPython and records executed outputs in the notebook files. The first import cell has no display output by design.

`run_all.sh` writes comparison CSVs to `runs/reproduced_v2/`. Set `SEISDAE_V2_OUT` to choose another output directory. It leaves the shipped V1 and V2 reference tables available for comparison; it regenerates the V2 checkpoint, rendered files and saved notebook outputs. For a standalone command that writes a table, the default directory is `results_v2/`. Use the environment variable to redirect it.

## Data and split

The source [Caltech P-phase collection](https://doi.org/10.22002/n47vy-s0s65) contains 181 event files. Each released channel has 200 samples at 100 Hz. An eligible aperture has 24 consecutive channel IDs and at most eight samples of shift spread. We take the block with the highest median source SNR, align using the source shifts, and form two 70-sample windows. The later P segment is the reference. The earlier segment is scaled and added at −5, 0, 5 or 10 dB. We score the real central samples, even when the model sees a padded 6,001-sample input.

| Cohort | Long Valley | Ridgecrest | Use |
|---|---:|---:|---|
| Training | 12 | 12 | Fit weights |
| Validation | 3 | 3 | Stop training and run development sensitivities |
| Earlier pilot | 3 | 3 | Excluded from V2 |
| Test | 133 | 12 | Fixed model comparisons and descriptive strata |

The earlier project selected the largest 18 events per site for development and pilot work. The remaining events were already evaluated in V1. V2 reuses this fixed benchmark and keeps test events out of every new fitting or selection decision. Three array-balanced outer folds additionally score each of the 30 development events once with separate inner stopping earthquakes. The smaller test-magnitude strata and site imbalance matter when interpreting any pooled gain.

### Rebuild the data from their sources

The default pipeline starts with the included cuts. To recreate them independently:

```bash
python -m src.data --out runs/rebuilt_prepared
python -m src.v2.noise_data --raw data/raw/CaltechDATA
python -m src.v2.noise_data --continuous
```

The first command downloads and verifies the Caltech archive and rebuilds the prepared arrays without overwriting the release. The second regenerates the disjoint validation channel blocks. The third fetches only the specified sample ranges of an independently recorded SCEDC Ridgecrest hour. [The source manifest](data/noise_v2/continuous.json) contains the URL, UTC timestamp, byte ranges, sample positions and SHA-256 digests. The three snippets share one recording and were not independently labeled earthquake-free. The paired Ridgecrest comparison uses the same three target events under all noise conditions.

### Reading the metrics

- `gain_db` compares the energy of the input residual with the output residual against the same reference. Positive values indicate improvement.
- `si_gain_db` is the change in channelwise zero-mean SI-SDR. `cc` reports signed correlation. A sign reversal can preserve SI-SDR while reversing first motion.
- `peak_ratio` compares the local arrival peaks after pre-onset baseline subtraction. One is the amplitude target. `polarity_agreement` scores the sign of the first local excursion; no analyst polarity labels are available.
- `pick_recovery` is the fraction of reference STA/LTA picks also found in the output. `pick_mae_ms` is timing error among matched picks. These are conditional agreement measures.
- `_lo` and `_hi` are 95% percentile intervals from 5,000 whole-earthquake resamples within the array. Timing and recovery are recomputed from counts. The size plot instead shows the range over five training seeds.

## Scope and credits

Noise and padding experiments are development sensitivities on six earthquakes; the external-noise comparison has three. The five-seed learning curves change optimizer update count as well as the number of training examples. The final decoder experiment updates only the last block. Full-network tuning and a larger from-scratch STEAD/FDSN run remain open. The original separately labeled pilot is retained. The report discusses possible event-family dependence, reference noise, array imbalance, and the difference between improving a waveform metric and detecting an earthquake.
